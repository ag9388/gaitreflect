What changed in v2

v1's robots walked with bird-like knees, "fell" because a keyframe pushed the hips into the floor, and had no face, so it was hard to tell which way they were walking. v2 rebuilds the robots, the defects and all 90 Beam runs.

Human knees

The thigh swings forward and the shin bends backward, like a person. The knee defect is now hyperextension: the shin bends forward past straight, beyond the rig's limit (−150° … +5°). Clamping it to the limit is not enough: the straight leg pushes the foot into the floor, which the verifier also rejects.

v1: thigh swung back, shin bent forward ("knee flip"), and the clamped "fix" looked stiff.

Physical falls

The defect is a posture that can't stand: the upper body leans or slides sideways until the center of mass leaves the feet's support polygon for 6+ frames. The fall itself is simulated with Bullet.

v1: a keyframe sank or tipped the root bone.

A face

An orange visor on the head and a plate on the chest mark the front, so you can always tell which way the robot is facing.

v1: plain boxes, front and back looked the same.

Walks forward

The hips travel forward while the stance foot stays planted, and the toes point the way the robot moves. The verifier checks both. Left and right now match a robot facing forward.

v1: walked in place; left/right were mirrored.

The reflection loop

Beam never grades its own work. Blender measures, Beam reasons and writes code, Blender measures again.

01

Verify

Play the walk cycle headless. Measure every face's area vs. rest pose, audit all vertex weights, check joint limits, and test whether the center of mass stays over the feet.

Blender · bpy/bmesh
02

Report

Turn the numbers into a structured prompt. How much it explains depends on the evidence level (L1–L3).

harness.py
03

Reflect

Beam diagnoses each issue ID and returns schema-checked JSON with an idempotent bpy fix script.

Beam via HF Inference Providers
04

Apply & re-verify

Run the script in a sandboxed Blender, save a new .blend, test again. Failures go back to Beam as history, up to 3 rounds.

apply_fix.py

PASS means zero verifier errors: no face over 1.5× stretch, no weights on non-adjacent bones, no joint outside its limit, no foot more than 2 cm into the floor, no sudden jump in any bone's motion, the upper body within ±20°, the CoM never outside the feet for 6+ frames in a row, and the robot still walks forward with the same stride. Out of scope: momentum (sudden stops), foot sliding, and outside forces such as pushes or slopes.

Run it yourself

Python 3.13 with pip install bpy pybullet (Blender 5.2 as a module; pybullet may need to build from source). Beam runs through Hugging Face Inference Providers with your HF_TOKEN.

# 1. generate the 30 episodes and check each is solvable (no API)
python3 make_bench.py --out episodes

# 2. Beam on 30 episodes × L1/L2/L3, up to 3 rounds each
export HF_TOKEN=...
python3 run_bench.py --effort high --token-budget 2300000

# 3. one robot, one level
python3 reflect_loop.py episodes/ep24.blend --mesh Robot --armature Rig --evidence L2

# 4. bake the 3D models (Bullet falls) and this page's data
python3 build_viewer.py --results results --out site
